# How We Used AI

We used AI as a production tool on this project. The problem, the local bound, and the ritual were team decisions. The model did not choose the brief.

## Where it helped

- Scaffolding the Vite/React prototype (screens, settlement maths, swipe). Faster than typing boilerplate.
- Turning a written mechanic (claim / pass / veto / slider) into working states.
- Checking GitHub Pages workflow files.
- Drafting structure for this wiki against the assignment outline, then we rewrote for voice.

It is good at **how**: files, layout, “make this button do that.”

## Where it was weak

- **What to work on.** Left alone, it offers campus maps, student discounts, and generic budgeting. That is the opposite of the brief. We had to keep pulling it back to a St Lucia kitchen.
- **Evidence.** If you let it, it invents interviews. We refused that. No fake quotes.
- **Tone.** First drafts sounded like a pitch deck written by a brochure. We cut adjectives until it sounded like people who have actually split a Woolies bill.
- **Permissions.** It cannot enable GitHub Pages for a repo you do not admin.

## How to read this wiki

If a sentence is doing no work, we tried to delete it. If a number is not from a study, we did not dress it up as one. The prototype is real. The field study is not, yet. AI did not get to blur that line.
